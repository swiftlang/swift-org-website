The Swift project once again participated in [Google Summer of Code](https://summerofcode.withgoogle.com) in 2026, helping newcomers to the open source ecosystem dip their toes into contributing to Swift and its growing ecosystem.

This year, we ran three projects, all of which were completed successfully:

* DocC language features in SourceKit-LSP
* Task and TaskGroup tracking for Swift Concurrency
* Qualified name lookup for swift-syntax

Here's a short summary of each project, with links to the full writeups to learn more.

### DocC Language Features in SourceKit-LSP

* Mentee: [Padmashree S S](https://github.com/Padmashree06)
* Mentors: [Matthew Bastien](https://github.com/matthewbastien) and [Prajwal Nadig](https://github.com/snprajwal)
* Project writeup: [\[GSoC 2026\] DocC Language Features in SourceKit-LSP](https://forums.swift.org/t/gsoc-2026-docc-language-features-in-sourcekit-lsp/89281)

This project extended SourceKit-LSP support in DocC with language feature support such as:
- "go to definition" for symbol links in doc comments, Markdown and Tutorial files
- diagnostics for broken or invalid symbol links in documentation
- clickable symbol links in documentation previews
- and syntax highlighting for DocC Markdown and Tutorial files. 

These features were implemented in SourceKit-LSP and are not tied to any specific editor,
unlocking IDE-grade documentation tooling across Visual Studio Code and any other IDE or editor that uses the Language Server Protocol.

### Task and TaskGroup Tracking for Swift Concurrency

* Mentee: [Ege Kaya](https://github.com/egekaya1)
* Mentors: [Alastair Houghton](https://github.com/al45tair), [Mike Ash](https://github.com/mikeash)
* Project writeup: [\[GSoC 2026\] Task and TaskGroup tracking for Swift Concurrency](https://forums.swift.org/t/gsoc-2026-task-and-taskgroup-tracking-for-swift-concurrency/89084)

This project adds the ability to find and inspect Swift Tasks at runtime by introducing a registry that tasks register with at runtime.
This allows inspecting a running application–on any platform–for any stuck or still running tasks that previously would be hard to discover without using a profiler like Instruments.

This project also keenly focused on the performance aspects of the registry, using strategies like optimizing for mechanical sympathy, minimizing false memory sharing, etc.
to enable the registry to have a minimal overhead over previous runtimes.

### Qualified Name Lookup for swift-syntax

* Mentee: [Filip Sakel](https://github.com/filip-sakel)
* Mentor: [Pavel Yaskevich](https://github.com/xedin)
* Project writeup: [\[GSoC 2026\] Qualified Name Lookup for swift-syntax](https://forums.swift.org/t/gsoc-2026-qualified-name-lookup-for-swift-syntax/89331)

This project continues a theme from [GSoC 2024](/gsoc2024/#lexical-scopes-for-swift-syntax), where another project introduced lexical scopes and unqualified name lookup in swift-syntax's `SwiftLexicalLookup` module. 
This year's project built on that foundation by adding *qualified* name lookup, allowing tools like linters, code generators, or macros to efficiently perform actions like looking up members of a type.
