The Swift project once again participated in [Google Summer of Code](https://summerofcode.withgoogle.com) in 2026, helping newcomers to the open source ecosystem dip their toes into contributing to Swift and its growing ecosystem.

This year we ran three projects, all of which completed successfully:

* DocC language features in SourceKit-LSP
* Task and TaskGroup tracking for Swift Concurrency
* Qualified name lookup for swift-syntax

We'd like to extend our sincere thanks to the contributors and mentors for the time and passion they've poured into these projects. 
Below is a short summary of each project, and links to complete detailed writeups if you'd like to learn more about these projects:

### DocC Language Features in SourceKit-LSP

* Mentee: [Padmashree S S](https://github.com/Padmashree06)
* Mentors: [Matthew Bastien](https://github.com/matthewbastien) and [Prajwal Nadig](https://github.com/snprajwal)

This project extended SourceKit-LSP support in DocC with language feature support such as:
- "go to definition" for symbol links in doc comments, Markdown and Tutorial files
- diagnostics for broken or invalid symbol links in documentation
- clickable symbol links in documentation preview
- and syntax highlighting for DocC Markdown and Tutorial files. 

These features were implemented in SourceKit-LSP and are not tied to any specific editor,
unlocking IDE-grade documentation tooling across every SourceKit-LSP-based editor, including VS Code and any other IDE using SourceKit-LSP.

![Diagnostic for an unresolved DocC symbol link in VS Code](/assets/images/gsoc-26/docc-lsp-diagnostics.png)

For a detailed writeup, including more screenshots and examples, read Padmashree's full writeup on the Swift forums: 
[\[GSoC 2026\] DocC Language Features in SourceKit-LSP](https://forums.swift.org/t/gsoc-2026-docc-language-features-in-sourcekit-lsp/89281).

### Task and TaskGroup Tracking for Swift Concurrency

* Mentee: [Ege Kaya](https://github.com/egekaya1)
* Mentors: [Alastair Houghton](https://github.com/al45tair), [Mike Ash](https://github.com/mikeash)

This project adds the ability to find and inspect Swift Tasks at runtime, by introducing a registry that tasks register themselves with at runtime.
This allows inspecting a running application–on any platform–for any stuck or still running tasks that previously would be hard to discover without using a profiler like Instruments.

A lof of the work in this project went into the performance aspects of the registry, optimizing for mechanical sympathy and minimizing false memory sharing etc,
allowing the registry to only have a minimal overhead over previous runtimes.

You can read Ege's full writeup on the Swift forums: [\[GSoC 2026\] Task and TaskGroup tracking for Swift Concurrency](https://forums.swift.org/t/gsoc-2026-task-and-taskgroup-tracking-for-swift-concurrency/89084).

### Qualified Name Lookup for swift-syntax

* Mentee: [Filip Sakel](https://github.com/filip-sakel)
* Mentor: [Pavel Yaskevich](https://github.com/xedin)

This project continues a theme from [GSoC 2024](/gsoc2024/#lexical-scopes-for-swift-syntax), where another project introduced lexical scopes and unqualified name lookup in swift-syntax's `SwiftLexicalLookup` module. 
This year's project built on that foundation by adding *qualified* name lookup, which allows tools like liters, code generators, or macros to find e.g. members of a type efficiently.

You can read Filip's full writeup on the Swift forums: [\[GSoC 2026\] Qualified Name Lookup for swift-syntax](https://forums.swift.org/t/gsoc-2026-qualified-name-lookup-for-swift-syntax/89331).
